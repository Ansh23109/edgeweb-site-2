Most "SEO checklists" mix up two different problems

Technical SEO — can search engines find, read and trust your pages — is a different problem from content SEO — is what's on the page actually what people are searching for. This checklist covers the technical half: the fixes that matter regardless of your industry, before a single word of new content gets written.

1. Crawlability and indexing

  • robots.txt isn't blocking pages it shouldn't. A single misplaced rule can quietly deindex an entire section of a site — check it directly, don't assume.
  • An XML sitemap exists, is submitted, and actually reflects the live site. A sitemap listing pages that 404, or missing pages that exist, both cause problems.
  • Canonical tags point to the right URL on every page — especially on sites with URL parameters, filters, or both www and non-www versions live.
  • No orphan pages. If a page isn't linked from anywhere else on the site, search engines struggle to find it no matter how good the sitemap is.

2. On-page fundamentals, done consistently

  • Every page has a unique title tag and meta description — duplicated or missing ones across a site are one of the most common issues we find on an audit.
  • One H1 per page, matching what the page is actually about, with a logical H2/H3 hierarchy underneath it — not a page that jumps from H1 straight to H4 because it "looked right" visually.
  • Every meaningful image has descriptive alt text — not just for accessibility, but because image search is a real, underused traffic source for most small businesses.
  • Internal links use descriptive anchor text ("see our pricing guide") instead of "click here" — it's a small thing search engines and users both read the same way.

3. Structured data (schema markup)

Schema doesn't directly boost rankings, but it does directly affect how a page is understood and how it can appear in search results — rich snippets, FAQ dropdowns, breadcrumb trails. The highest-value schema types for most business sites:

  • Organization / LocalBusiness — establishes who you are, where you're based, and how to contact you.
  • BreadcrumbList — shows the page's position in the site structure directly in search results.
  • FAQPage — for pages with genuine, visible Q&A content matching the schema exactly.
  • Service / Product — for pages describing something specific you sell or offer.

The rule that matters more than the markup itself: structured data has to describe content that's actually visible on the page. Schema that doesn't match what a visitor sees is a real risk, not a shortcut.

4. Core Web Vitals and performance

Page speed affects both rankings and, more directly, whether a visitor sticks around long enough to convert. The three metrics that matter:

MetricWhat it measuresGood target
LCP (Largest Contentful Paint)How fast the main content becomes visibleUnder 2.5 seconds
INP (Interaction to Next Paint)How responsive the page feels when clicked or tappedUnder 200 milliseconds
CLS (Cumulative Layout Shift)How much the page jumps around while loadingUnder 0.1

The most common cause of a failing score isn't exotic — it's usually unoptimized images, a render-blocking script loaded too early, or web fonts that shift layout while they load. Fixing those three covers the majority of real-world Core Web Vitals problems.

5. Mobile-friendliness, checked for real

Google indexes the mobile version of a site by default, which means a site that looks fine on desktop but breaks on a real phone is being judged on the broken version. Check on an actual device, not just a resized browser window — touch targets, font size, and horizontal scrolling issues often only show up that way.

The order to actually do this in

Crawlability and indexing first — none of the rest matters if pages aren't being indexed at all. Then on-page fundamentals, since they're the fastest to fix and compound across every page. Structured data and performance can happen in parallel once the foundation is solid. Content strategy — the other half of SEO — only pays off once this technical layer is in place underneath it.
