# EdgeWeb — Next.js site

This is the EdgeWeb marketing site, migrated from static multi-page HTML to
Next.js 16 (App Router), with the full SEO/AI-search audit recommendations
integrated (see `EdgeWeb_SEO_Audit_and_Growth_Plan.pdf` if you still have it).

## What changed vs. the old static site

- **Framework**: plain HTML pages → Next.js App Router (`/app`), one
  `page.js` per route, each with a real Next.js `metadata` export instead of
  hand-written `<meta>` tags.
- **Canonical domain fixed** (audit §3.1): everything now points at
  `https://www.edgeweb.co`. `next.config.js` 301-redirects the apex
  `edgeweb.co` to `www` — this only takes effect once **both** domains are
  attached to the project on your host.
- **Structured data** (audit §7): `ProfessionalService` + `WebSite` schema
  site-wide, `Service` + `BreadcrumbList` + `FAQPage` schema on every service
  page, `FAQPage` on the homepage and `/faq`. See `lib/schema.js`.
- **New indexable pages** (audit §3.3): `/about`, `/case-studies`, `/faq` are
  now real routes with their own titles/descriptions, not homepage anchors.
  The homepage keeps its original flowing `#about`/`#work`/`#faq` sections
  for on-page UX; `sitemap.xml` only lists the real pages.
- **Meta titles & descriptions** (audit §6): every page carries the exact
  copy recommended in the audit.
- **`llms.txt` / `llms-full.txt`** (audit §8): served from `/public`, wired
  into `next.config.js` with a `text/plain` content type.
- **Dynamic `sitemap.xml` / `robots.txt`**: generated by `app/sitemap.js` /
  `app/robots.js` (Next's Metadata Route convention) instead of static files,
  so they can't drift from the actual route list again.
- Fixed a handful of `<a href="#top">` links that had lost their `href=`
  attribute in the original HTML (logo, some nav CTAs) and were silently
  dead links.
- Fixed the homepage's discovery-form modal, whose markup lived inside an
  HTML comment in the original file — the "Not sure what you need?" CTA
  referenced it but it never actually rendered on the homepage.

## How the migration is built

Given the size and hand-tuned animation/CSS in the original design (preloader,
custom cursor, magnetic buttons, a 6-step discovery-form modal, scroll
reveals), the goal was to preserve it **exactly** rather than rewrite it as
idiomatic React and risk breaking it. So:

- `components/Header.js`, `MobileMenu.js`, `Footer.js`, `StickyCtas.js`,
  `DiscoveryModal.js`, `ChromeEffects.js` are real JSX — they were 100%
  identical (or near-identical) across every old page, so they're now a
  single source of truth.
- Each page's **unique** body content, CSS and vanilla-JS behaviour were
  extracted verbatim into `/content/<page>/{main.html,style.css,script.js}`
  and are read server-side (`lib/content.js`) and rendered via
  `dangerouslySetInnerHTML` / `next/script`. This is still fully
  server-rendered HTML (crawlers see complete content), just not hand-typed
  JSX for a few thousand lines of animation-heavy markup.
- Every page uses plain `<a>` tags rather than `next/link`, matching the
  original site's full-page-navigation behaviour — this also avoids the
  vanilla scripts' global event listeners double-registering across
  client-side route transitions.
- The 8 service pages share one CSS/JS bundle (`content/services-detail/`)
  since the originals were byte-for-byte identical apart from the page copy.

## Before you deploy

A few things the audit flagged as drafts to verify — still true here:

- **Logo / OG image**: `lib/schema.js` and page metadata reference
  `/logo-edgeweb.png` and `/og-image-edgeweb-home.jpg`, neither of which
  exists yet. Add real files to `/public` (1200×630 for the OG image).
- **Address fields**: `organizationSchema()` in `lib/schema.js` only sets
  `addressCountry: "IN"` — add `addressRegion`/`addressLocality` if you want
  Google Business Profile / local-pack eligibility.
- **`.env` was previously committed to git** with `ADMIN_PASSWORD_HASH`,
  `ADMIN_PASSWORD` and `SESSION_SECRET` in it. It's now git-ignored going
  forward (see `.env.example`), but **rotate those values** — they're still
  in your git history.
- Attach both `edgeweb.co` and `www.edgeweb.co` to the project on your host
  so the redirect in `next.config.js` actually fires.
- Re-validate all schema with Google's Rich Results Test after deploying.

## Local development

```bash
npm install
cp .env.example .env.local   # fill in SMTP + admin values
npm run dev
```
